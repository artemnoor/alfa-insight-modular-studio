# T08 request timeouts must begin at network dispatch

**Date:** 2026-10-22
**Files:** shared/backend/polza_transport.mjs; modules/02-news-intelligence/backend/provider_transport.mjs; T08/T09 callers; module adapter and Workbench
**Severity:** high

## Problem

T08 repeatedly stopped after several charged calls with a timeout, did not reach T09, and reported all cost unknown. Manual repeats paid for already completed steps.

## Root Cause

Parallel classification branches created AbortSignal timers before a serial spending gate. Queue wait consumed network timeout before requests were dispatched. Top-level reasoning_effort is silently ignored by Polza, adding unnecessary reasoning latency/output cost. Usage was only returned at child-process completion; a timeout erased the known subtotal. The fetch deadline also ended at headers rather than the complete body.

## Solution

Pass lazy per-request deadlines through a request-scoped AsyncLocalStorage transport. Serialize actual sends and account full responses; keep queue time within a separate overall deadline. Use nested reasoning.effort. Checkpoint billing at send/response boundaries, retain confirmed subtotal and count unknown charges separately. Cache complete real JSON replies with account/request-scoped hashed keys. Use atomic pending markers and explicit uncertain-payment retry selection. Cancel queued work after fatal classification failure without abandoning accounting for the already sent request.

## Prevention

Test queue waits longer than an individual request timeout, stalled body reads, subprocess interruption after several known charges, manual resume and concurrent duplicate attempts. Distinguish cached real model responses from fixtures and current cost from original billing. Consult the provider's own parameter documentation. Never log prompts, bearer keys or client profile contents in transport diagnostics.
