## Назначение и владелец кода

Модуль позволяет исследовать ход агентной проверки: версии плана, фактически выполненные инструментальные вызовы, пропущенные шаги, источники и стоимость. Он оборачивает существующий `run_agent`; отдельной второй версии аналитического ядра не создаёт.

Основные владельцы:

- `modules/07-ai-agent/backend/agent_orchestrator.py:545` — каноническая реализация `run_agent`, ограничения по итерациям/вызовам/токенам/стоимости/времени, модельные запросы, исполнение инструментов, проверка итоговых утверждений и сохранение истории. Модуль использует локальные профили, события, граф, T08/T09-архив и RAG.
- `modules/07-ai-agent/backend/adapter.py:15` — fixture-адаптер с внедрёнными детерминированными `request_fn` и `semantic_verify_fn`; `:56` — внешний запуск; `:107` — Local Data без AI.
- `drive_data_analysis_2026-10-20/agent_orchestrator.py:1-13` — thin compatibility import к каноническому файлу модуля.
- `modules/07-ai-agent/frontend/ModulePage.tsx:4-23,26-83` — представление плана отдельно от списка реальных вызовов, шагов, результатов, источников и стоимости.
- `shared/frontend/ModuleWorkbench.tsx:43-104,150-185,199-243` — общий выбор режима, входов, запуск и provenance. В fixture-режиме запуск тестовый; External AI доступен только при server opt-in.
- `modules/07-ai-agent/fixtures/scenarios.json:1` и `tests/test_module.py:7-17` — четыре сценария и тестовый API dispatcher.

## Алгоритм и зависимости

Оркестратор требует валидный ID профиля и события и проверяет модель по allowlist (`agent_orchestrator.py:183-194,545-570`). Он вводит верхние пределы, по умолчанию до 4 итераций, 10 инструментальных вызовов, 24 000 токенов, 5 ₽ и 120 секунд (`:25-37,545-559`). Сначала агент регистрирует план; функции `submit_research_plan`, `revise_research_plan` и `skip_research_step` формируют историю версий и политику разрешённых инструментов (`:956-1044`). Доступны профиль, факты события, контекст бизнес-связей, поиск новостей, RAG и проверка доказательств (`:53-98,718-928`). Когда модель не вызывает предусмотренную необязательную проверку, guard может выполнить оставшиеся пункты плана (`:1088-1122`). Финальные тезисы проходят структурную проверку и сверку по зарегистрированным доказательствам (`:491-528,1272-1365`).

Fixture действительно проходит по `run_agent`, но ответ модели, RAG и часть источников заменены deterministic transport/fixture данными в адаптере (`adapter.py:15-54`). Поэтому он проверяет интерфейс orchestration и инструменты, а не актуальное поведение или качество внешней нейросети. Fixture использует временный SQLite-файл, а не рабочую историю. External AI собирает выбранный профиль и событие из локальных данных, может включить связанные события и доступную бизнес-сеть, затем вызывает тот же оркестратор и его провайдера (`adapter.py:56-105`).

## API-контракт

Общий module API версии `1.0` (`shared/contracts/module-api.ts:1-33`, `shared/contracts/module_api.py:1-30`):

- `GET /api/modules/ai-agent/health`, `/scenarios`, `/options`.
- `POST /api/modules/ai-agent/run` с `{ mode, scenarioId?, input? }`; `mode` — `fixture`, `local_data` или `external_ai`.
- `POST /api/modules/ai-agent/tests` запускает fixture-набор.
- Успешный ответ содержит `module`, `mode`, `status`, `data`, `provenance`, `validation`; ошибка — `contractVersion` и `error.code/message/detail` (`shared/backend/modules_api.py:162-303`).
- Результат агента включает `planHistory`, `plannedTools`, `planSteps`, `toolCalls`, `analysis`, `tokenUsage`, `costRub` и `provenance`. UI отдельно строит множества planned/called и явный список невыполненных запланированных инструментов (`ModulePage.tsx:4-23`).

External запуск блокируется, если не выполнены opt-in, key, allowlist, budget или входная валидация (`adapter.py:56-74`). Вызовы сериализуются общим lock; повторный внешний запуск не отправляется параллельно (`shared/backend/modules_api.py:234-242`).
